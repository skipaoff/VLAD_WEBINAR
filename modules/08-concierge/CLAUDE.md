# Инструкция агенту: написать лидам от лица владельца

Тебя попросили написать людям, которым можно продать то, что мы собрали. Это не рассылка
и не бот: сообщения уходят с живого аккаунта владельца, и каждое пишешь ты — руками,
под конкретный бизнес.

**Мозги здесь твои.** У модуля нет ключа Anthropic и нет своей модели. `concierge.py` —
это руки: он умеет отправить, выдержать паузу, показать ответы и остановиться на лимите.
Что писать — решаешь ты, в этом чате.

Прочитай `knowledge/how-to-write/03-limits.md` до того, как что-то отправлять.

## Шаг 1. Проверь доступ

```bash
python concierge.py check
```

Ответил «аккаунт не авторизован» — попроси владельца выполнить `python concierge.py login`
и ввести номер и код. Это делает он сам, код в чат не диктуется.

Нет `.env` — попроси `TG_API_ID` и `TG_API_HASH` с my.telegram.org. Ключа модели не проси:
его тут не должно быть.

## Шаг 2. Прочитай, что мы предлагаем

Три файла в `knowledge/what-we-offer/`. Не заполнены — заполни их из контекста: сайт,
ассистента, креативы и рекламу мы делали в этом же чате, ссылка на готовый сайт есть выше.
Спроси только цену, если её нигде не называли.

Потом два файла в `knowledge/how-to-write/` — как писать первым и что отвечать. Они уже
написаны, менять их не нужно.

## Шаг 3. Посмотри лидов

```bash
python concierge.py leads
```

Список берётся из `leads.csv`: username, имя, бизнес и строка про то, что с ним не так.
Потолок — двадцать человек, больше скрипт не примет.

Файла нет — попроси владельца заполнить `leads.example.csv`. Сам никого не ищи и в
список не добавляй.

## Шаг 4. Напиши каждому своё сообщение

Это главная работа. На каждый лид — отдельный текст по правилам из
`knowledge/how-to-write/01-first-message.md`: конкретная деталь про его бизнес, что с
этим можно сделать, лёгкий вопрос. Три-четыре строки, без ссылок и без цен.

```bash
python concierge.py queue --to @username --text "…"
```

Скрипт не примет два одинаковых текста и не даст написать тому, кому уже писали.
Если для лида нечего сказать по существу — не пиши ему вообще, лучше девять хороших,
чем десять.

## Шаг 5. Покажи владельцу и дождись «ок»

```bash
python concierge.py drain
```

Без `--confirm` это только план: кому и что уйдёт. Покажи его целиком и жди.
Владелец сказал «ок» — запускай:

```bash
python concierge.py drain --confirm
```

Отправка идёт по одному, с паузами в несколько минут и длинной паузой каждые пять.
Десять сообщений — это примерно полчаса. Запускай в фоне и не жди в терминале.

Telegram ответил ограничением — скрипт остановится сам. Скажи об этом владельцу прямо
и на сегодня прекрати. Не пробуй с другого аккаунта.

## Шаг 6. Следи за ответами

```bash
python concierge.py inbox
```

Показывает новое с прошлой проверки. Заглядывай раз в несколько минут, пока сессия открыта.

На каждый ответ пиши сам, сверяясь с `knowledge/how-to-write/02-objections.md`:

```bash
python concierge.py reply --to @username --text "…"
```

Отвечай быстро — в холодной переписке первые минуты решают. Но не мгновенно: человек
писал пятнадцать секунд, ответ через две выглядит как автомат.

Кто-то попросил не писать — скрипт вычеркнет его сам. Увидел раньше скрипта — вычеркни:

```bash
python concierge.py stop --to @username
```

## Шаг 7. Отдай сделку человеку

Как только звучит «давайте», «сколько», «когда сможете» — переписка кончилась, началась
сделка. Скажи владельцу, кто и что написал, и дальше он сам.

## Чего не делать

- Не отправлять без «ок» владельца.
- Не писать никому, кого нет в `leads.csv`.
- Не отправлять один и тот же текст двоим.
- Не обходить лимиты и не править `config.json`, чтобы «прошло больше».
- Не продолжать после ограничения от Telegram.
- Не обещать сроков, результата и цен, которых нет в `knowledge/what-we-offer/`.
- Не просить ключ модели: думаешь ты, а не модуль.
