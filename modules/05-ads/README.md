# Запуск рекламы

Агент берёт готовый сайт и видео-креатив и доводит дело до включённой рекламы в Facebook и
Instagram. Работает шестью субагентами, и после каждого этапа обновляет экран прогона: зритель
видит, кто сейчас работает, что уже разобрано и что получилось.

## Как это выглядит

Справа в панели артефактов открывается экран прогона. Сверху — пиксельный офис: шесть
субагентов, за компьютер садится тот, чей этап идёт. Ниже — карточки этапов. У каждой
законченной карточки три вещи: что агент разобрал, что получил и документ с полным
результатом, который раскрывается прямо на экране.

## Шесть субагентов

| | Субагент | Что делает | Скилл |
|---|---|---|---|
| 01 | Техник | подключается к кабинету, проверяет права, страницу, оплату | `account-onboarding`, `fb-api` |
| 02 | Аналитик креатива | разбирает видео по чек-листу: зацеп, понятность без звука, призыв | `creative-analyzer` |
| 03 | Таргетолог | находит город, подбирает интересы, считает охват из кабинета | `targeting-expert` |
| 04 | Редактор | пишет основной текст, заголовок, описание и кнопку | `creative-copywriter` |
| 05 | Медиабайер | собирает план кампании: цель, бюджет, где показывать, названия | `campaign-manager`, `naming-rules` |
| 06 | Контролёр | проходит чек-лист, спрашивает «включаю?», запускает | `safety_rules`, `fb-api` |

## Вопросы

Вводные — бюджет, страна, город, куда ведём людей — приходят в промпте, агент их не
переспрашивает. Единственный вопрос во время работы — перед самым запуском: «Запускаю на
такой-то бюджет. Включаю?» Без «да» реклама не включается.

## Что нужно заранее

**Три значения от рекламного кабинета** — в `.env`, по образцу `.env.example`:

| | Где взять |
|---|---|
| ID кабинета | Ads Manager → Настройки аккаунта, или в адресной строке после `act=` |
| Access Token | developers.facebook.com → приложение → Marketing API → Tools → права `ads_management` и `ads_read` → Generate Token |
| App Secret | там же, Settings → Basic |

**В самом кабинете:** привязанная страница Facebook и способ оплаты. Без платёжки кампания
создастся, но не запустится.

**Видео-креатив** — в `kreativ/video.mp4`. Лучше вертикальное 9:16: оно пойдёт в сторис и рилс.

## Что внутри

```
.claude/skills/
  ads-agent/            порядок этапов, реплики, экран прогона и офис
  fb-api/               вызовы Facebook напрямую по ключам
  account-onboarding/   подключение кабинета
  creative-analyzer/    разбор креатива
  targeting-expert/     аудитория
  creative-copywriter/  тексты объявлений
  campaign-manager/     структура кампании
  naming-rules/         названия
config/knowledge/       правила безопасности, метрики, практики, ошибки, гео
config/                 шаблоны кабинета, брифа, креативов, названий
kreativ/                видео
cache/                  документы прогона
build/                  экран прогона
history/                лог запусков
```

## Что агент не делает

- **Не считает оценку риска креатива.** Она строится на показах и кликах, а у видео до
  запуска их нет. Вместо неё — разбор по чек-листу.
- **Не строит похожие аудитории.** Для них нужна исходная аудитория, которой у нового
  кабинета нет.
- **Не создаёт группы после 18:00** по времени кабинета без явного решения человека — так
  записано в правилах безопасности. Вечером агент скажет об этом в вопросе перед запуском.
- **Не оптимизирует кампанию после запуска.** Его задача — правильно запустить.

## Два режима

**Обычный** — вся работа вживую, от подключения до запуска.

**Прогрев и эфир.** Прогрев проходит все этапы до вопроса перед запуском и ничего не
создаёт в кабинете — делается заранее. На эфире агент берёт разбор из `cache/`, а
подключение и запуск делает вживую. Включается фразой «прогони по кэшу». После смены
клиента прогрев обязателен.
