# Инструкция агенту: поставить продавца

Тебя попросили подключить AI-продавца и дали ссылку на этот модуль. Сайт бизнеса уже
сделан на прошлых шагах — знания для продавца берутся оттуда.

Модуль намеренно простой: один файл кода, четыре файла знаний, три зависимости. Ничего
не усложняй и не дописывай архитектуру.

## Шаг 1. Спроси токен бота

Проверь, есть ли `.env`. Если нет — попроси одним сообщением:

```
Для продавца нужны две вещи:

1. Токен бота — напиши @BotFather, /newbot, придумай имя.
   Он вернёт строку вида 12345:AA...

2. Ключ Anthropic — console.anthropic.com, раздел API Keys.

Положи их в .env рядом с bot.py, образец в .env.example.
В чат не пиши, я прочитаю из файла.

Если хочешь, чтобы продавец отвечал голосовыми — добавь туда же
ключ ElevenLabs, а в tenant.json впиши id голоса, чей это голос
и какой он по характеру. Нет — работает текстом, это нормально.
```

Ключи в чат не принимай и в своих сообщениях не повторяй.

## Шаг 2. Собери данные о бизнесе

**Если сайт делали в этом же чате** — всё бери оттуда: услуги, цены, адрес, часы,
преимущества, тон. Спрашивай только то, чего на сайте нет: как зовут продавца и куда
слать заявки.

**Если чат новый и сайта рядом нет** — спроси одним сообщением и жди:

```
Расскажи про бизнес, чтобы продавец знал, что продаёт:

1. Что за бизнес, город, ссылка на сайт если есть
2. Услуги и цены — списком, как есть
3. Чем отличаетесь от соседей
4. Кто ваши клиенты и с чем к вам приходят
5. Чего они обычно боятся перед покупкой
6. Как записаться: адрес, часы, телефон
7. Гарантии и как оплата
8. Чего вы не делаете
9. Как зовут продавца и куда слать заявки
```

Чего человек не назвал — того в знаниях не будет, и продавец об этом промолчит.
Не выдумывай за него ни цен, ни гарантий.

## Шаг 3. Разложи по папкам знаний

Папки две, и только две.

`knowledge/what-to-sell/` — заполняешь ты, по разделам:

| Раздел | Что туда |
|---|---|
| `offer/` | что предлагаем одной фразой, чем отличаемся |
| `product/` | услуги, как проходит визит, доказательства |
| `prices/` | прайс целиком, от чего зависит цена |
| `audience/` | кто приходит и с чем, чего боятся, когда готовы |
| `terms/` | как записаться, гарантии и оплата, границы |

`knowledge/how-to-sell/` — **не трогай**. Там методология продаж, она одинаковая для
любого бизнеса и уже написана. Исключение одно: в `01-conversation.md` есть блок
«Роль и манера» — впиши туда имя продавца, язык и тон.

Прайс переноси один в один. Продавцу запрещено называть числа, которых нет в
`prices/01-current.md`, поэтому неполный прайс превращает разговор в «уточню и вернусь».

Заполни `tenant.json`: бренд, имя продавца, язык, куда слать заявки, сайт. Если голос
нужен — блок `voice`: id голоса, чей он и какой по характеру.

Меток `{{...}}` не должно остаться ни одной. Бот не стартует, пока они есть.

## Шаг 4. Запусти

```bash
cd modules/06-sales-bot
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python bot.py
```

Бот работает long polling'ом — ни туннеля, ни белого IP, ни вебхука не нужно. Запускай
в фоне и оставь работать.

## Шаг 5. Проверь сам

Напиши боту `/start`, потом «сколько стоит» и посмотри ответ. Проверь три вещи:

1. цена названа из файла знаний, а не выдумана;
2. в конце сообщения есть вопрос;
3. тон совпадает с сайтом.

Если что-то не так — правь файл знаний, а не код.

Покажи человеку скриншот переписки одним сообщением и скажи, что дальше он может писать
боту сам.

## Чего не делать

- Не переписывать `bot.py` под «правильную архитектуру». Он такой намеренно.
- Не добавлять админку, этапы воронки, базу данных и мини-апп.
- Не придумывать цены, сроки и гарантии, которых нет на сайте.
- Не просить ключи в чат.
- Не запускать вторую копию бота с тем же токеном: Telegram отдаёт сообщения только
  одному процессу, и оба начнут терять сообщения.
