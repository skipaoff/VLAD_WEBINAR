# Сайт клиники: шаг, показ, вопрос

Работа настоящая. Артефакт показывает только то, что уже сделано, и после
каждого шага человек решает, идти дальше или поправить.

## Как устроен цикл

Один шаг это всегда четыре действия подряд:

1. Сделал работу.
2. Дописал результат в `build/state.json`: свой шаг перевёл в `done`,
   следующий в `run`, положил находки. В `question` написал, что спрашиваешь.
3. `python .claude/skills/stoma-demo/artifact.py` собирает `build/Сборка.html`.
4. Опубликовал: инструмент **Artifact**, `file_path` всегда один и тот же
   `build/Сборка.html`, `favicon` один и тот же на весь прогон. Первый раз
   даёт адрес, дальше страница обновляется по нему же.

После этого **задай вопрос в чат и остановись**. Не начинай следующий шаг,
пока человек не ответил. Он может сказать «дальше», может поправить факт,
может поменять решение: тогда правишь и публикуешь снова.

Вопрос короткий и по делу: не «продолжаем?», а что именно человек может
изменить. «Ведущей поставил имплантацию, она дороже и с ценой. Оставляем или
берём виниры?»

## Состояние

```json
{
  "clinic": "Comfort Dental",
  "subtitle": "сімейна стоматологія на Троєщині, comfort-stom.kiev.ua",
  "site": null,
  "folder": "сайт/",
  "updated": "31.08, 17:20",
  "question": { "title": "Идём дальше?", "text": "..." },
  "steps": [ { "id": "dna", "title": "ДНК клиники", "status": "done",
               "note": "одна строка о чём шаг",
               "chips": ["короткие находки"],
               "items": [ { "t": "что сделал", "s": "done" } ],
               "nums": [ { "v": 10, "t": "позиций прайса" } ],
               "shots": [ { "path": "build/shots/hero.png", "caption": "первый экран" } ] } ]
}
```

Статусы: `wait`, `run`, `done`, `warn`. `warn` это «сделано, но человеку надо
решить»: например в контактах только городской номер и мессенджера на нём нет.

`chips` это находки словами клиники, а не пересказ. `items` это что ты делал.
`nums` две-три цифры, которые видно издалека.

Заготовка состояния со всеми десятью шагами лежит в `state.example.json`
рядом с этим файлом: скопируй её в `build/state.json` и заполняй.

## Шаги

**01. ДНК клиники.** Открой сайт клиники по ссылке: услуги, цены, врачи,
оборудование, гарантии, адрес, ориентиры, часы, соцсети, акции. Пройди
внутренние страницы услуг. Ответь тремя строчками: чем клиника отличается,
чем это доказывается, каким голосом говорит. Ссылки нет: заполняй
`klient/ANKETA.md` вопросами по блокам.

**02. Целевая аудитория.** Кто платит в этой нише и в этом районе, на каком
этапе решения приходит, чего боится. Два-три сегмента. Вывод должен быть
применимым: какой сегмент главный и какой факт снимает его главный страх.

**03. Конкуренты рядом.** Две-три клиники того же района. Смотри одно: что
показано и что спрятано. Цены, страницы услуг, живые фото, врачи с именами.
Не пиши про конкурента того, чего не видел на его сайте.

**04. Оффер и первый экран.** Ведущая услуга, три факта первого экрана, строка
отстройки, цена «від». Ведущая это дорогая услуга с ценой и доказательствами,
а не любимая. Здесь вопрос человеку обязателен: это решение, а не факт.

**05. Структура сайта.** Блоки по порядку и что в каждом.

**06. Сборка по паттерну.** Vite + React + TypeScript + Tailwind в папке
`сайт/`, лендинг в одном `App.tsx`, данные в `src/content.ts`. Строго по
`PATTERN.md` рядом с этим файлом: те же классы, те же хуки, мозаика
MaskedCard, фиксированный navbar. Прелоадер не делай. Тексты клиники
переноси дословно.

**06б. Скролл-герой.** Если в проекте есть `assets/scroll/vid`, первый экран
это полёт по клинике, который прокручивается колесом. Клипы и постеры клади в
`public/scroll/`, движок в `src/vendor/scrubEngine.js` (в конец файла допиши
`export default mountScrollWorld;`), компонент в `src/components/`. В нём
меняешь только тексты четырёх сцен и телефон в кнопке.

Ловушки, все уже обойдены в компоненте, не «упрощай» их:

- в своём CSS пиши `min-height: 100%`, не `height`, иначе скроллером станет
  `body` и видео не перематывается
- слои движка это `position: fixed`, после полёта их надо гасить
- мёртвый экран под полётом убирается отрицательным нижним отступом
- стили движка лежат в `@layer sw` и проигрывают обычному CSS: переопределения
  типографики обязательны
- Tailwind ставит `video` правило `height: auto` и ломает `object-fit: cover`:
  нужен принудительный `width:100%; height:100%; cover`, проверь на 390
- телефону отдавай лёгкие копии клипов с суффиксом `-m`
- шапку над полётом делай прозрачной, читаемость давай градиентом сверху,
  а не обводкой букв

Видео в проекте нет: собирай обычный первый экран из паттерна, это нормально.

**07. Страницы услуг.** На каждую услугу страница на hash-роутинге `#/p/slug`:
интро, этапы, преимущества, полный прайс раздела, пакеты, вопросы и ответы
аккордеоном, кнопка записи, чипы на остальные услуги. Счётчик готовых страниц
держи в `nums`, он должен расти.

**08. Запись и мессенджеры.** Модалка записи: имя, телефон, услуга с
предвыбором той, со страницы которой пришли, комментарий. Кружочки только тех
мессенджеров, что у клиники есть. Городской номер это не мессенджер: если
других контактов нет, ставь шагу `warn` и спрашивай мобильный.

**09. Самопроверка.** Каждый пункт отдельным `items`, не прошло значит `warn`,
а не тихая галочка:

- `button { color: inherit; appearance: none }` в глобальном CSS, иначе Safari
  красит текст кнопок синим
- ширины 390, 768, 1024, 1440 проверены программно на горизонтальное
  переполнение, а не глазами
- каждый клик ведёт в живое место, страницы услуг открываются по прямой
  ссылке с хешем и по кнопке «назад»
- на сайте не осталось текстов паттерна: Dental Care, Smile Gallery и прочих
- `npm run build` проходит

**10. Готово.** Сними реальные скриншоты собранного сайта и положи их в шаг
через `shots`: первый экран, страница услуги, мобильная версия. Скриншоты
уходят в артефакт целиком, поэтому держи их шириной до 1400 и следи за
размером файла страницы, потолок 16 МБ.

Скриншоты снимай через Playwright:

```
npx playwright screenshot --viewport-size=1280,900 http://localhost:5173/ build/shots/hero.png
```

В `site` положи адрес, где сайт лежит, в `folder` папку проекта.

## Чего не делать

- Не отмечать шаг сделанным заранее и не рисовать находок, которых не было
- Не идти дальше без ответа человека
- Не публиковать артефакт под новым `file_path`: адрес должен остаться прежним
- Не выдумывать цены, гарантии, стаж и имена
- Не ставить чужие фотографии людей
- Не заменять слова клиники «более продающими»
